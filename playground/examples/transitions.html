Transitions

Velin holds mounting and unmounting nodes in the DOM long enough for a CSS transition to play. On mount, the node gets .vln-entering for two animation frames. On unmount, it gets .vln-leaving until the CSS transition-duration (max across all properties) + 50 ms elapses. Write CSS against those two class names.

Fast interactions cancel gracefully: re-toggling a vln-if or navigating back to a vln-route mid-leave revives the same node (CSS reverses back to natural state); rapid updates on vln-loop or template swaps on vln-fragment fast-forward pending ghosts so nothing piles up on screen.

vln-if

Fades in on mount, fades out on unmount. Re-toggle mid-leave to see the same node revive.

vln-loop (keyed)

Remove an item from the middle — the correct row animates out and the others stay put. That's the keyed diff at work. Positional vln-loop:item="items" would visually shift the list up instantly and animate the trailing slot instead. Also try clicking Clear mid-animation: the pending ghosts get fast-forwarded.

vln-fragment (template swap)

Swap templates back and forth quickly — the old card fades out while the new one fades in; a third swap mid-leave FFs the pending ghost.

vln-route

Home About
HOME
Slides in from the right, slides out to the left. Navigate away and back before the leave finishes — same node revives.
ABOUT
Two routes share the same animation contract; the leaving one slides away while the entering one slides in.

The library only owns the timing — the animation itself is CSS you write. Any element with no transition/animation removes synchronously, so this is zero-cost when unused.
